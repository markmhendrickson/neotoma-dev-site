Documentation

Neotoma is the system of record for AI agents: a record, not recall. These docs describe what the current build does. Pages under foundation/ state the design, so read them with the build in mind; where the two differ, the code and the README are the reference.

Applies tomain; the latest release is v0.25.0.

A running Neotoma server also serves these files at its own /docs route. To install and try Neotoma, start with the README.

Start here#

  • Developer getting started: local development setup with SQLite and the local filesystem.
  • CLI reference: every neotoma command.
  • MCP overview: connect an agent host over MCP, with a guide per host.
  • REST API and the OpenAPI spec: largely the same capabilities over HTTP, as a separate implementation from the MCP server.
  • Integrations matrix: every documented host and how it connects. The README table covers the common hosts; the matrix also lists hosts that are configured by hand.

How the record works#

  • Architecture: sources, observations, entities, snapshots, and relationships.
  • Reducer: how the current value of each field is computed from observations.
  • Observation architecture: how observations are stored and linked to sources.
  • Determinism: what is derived from inputs, and how.
  • Atomic corrections: apply a bounded set of corrections in one transaction (main; not in v0.25.0).

Foundation#

  • Core identity: what Neotoma is and is not.
  • Product positioning: the category and how it is described.
  • Problem statement and philosophy.

Folder map#

Folder Holds
developer/ Setup, CLI, MCP, and release guides for people building with or on Neotoma
api/, reference/ API and reference material
architecture/, subsystems/ Design of the data model and its parts
integrations/ Host-by-host integration status
foundation/ Identity, positioning, and principles
security/ Practices, threat model, and advisories
releases/ Release material
icp/, use_cases/ Who Neotoma is for, and example uses

Other folders (plans/, proposals/, prototypes/, reports/, implementation/) are working material and are not served by the /docs route unless internal docs are enabled.

Limits worth knowing before you rely on the record#

  • Provenance shows the evidence trail for a value, not that an agent read its source correctly.
  • Known limitations lists the specific ones, grouped as writes and corrections, reads and export, identity and attribution, surfaces and logs, and install and setup, each with what you will observe, any workaround, and its tracking issue.

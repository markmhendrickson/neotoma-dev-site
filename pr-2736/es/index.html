01 · Comparar

El recuerdo y un sistema de registro responden a preguntas distintas

La memoria y la recuperación ayudan a conservar y encontrar contexto. Un sistema de registro calcula valores actuales a partir de observaciones aceptadas y conserva el camino hasta las pruebas de cada campo.

Neotoma está dirigido a desarrolladores y operadores cuyos agentes trabajan con hechos que cambian entre herramientas. Tú eliges qué entra en la instancia local y qué herramientas la utilizan.

  1. ¿Qué se guarda?

    Recuerdo

    Normalmente, un resumen de lo visto por el agente.

    Sistema de registro

    Cada hecho registrado como observación vinculada a su fuente.

  2. ¿Qué ocurre cuando cambia un hecho?

    Recuerdo

    El texto nuevo suele quedar junto al anterior o sustituirlo.

    Sistema de registro

    Una regla por campo selecciona el valor actual; las observaciones anteriores permanecen en el historial.

  3. ¿Cómo sabes por qué un valor es actual?

    Recuerdo

    Sueles depender de la explicación del propio agente.

    Sistema de registro

    Cada campo actual identifica la observación que lo estableció.

  4. ¿Qué lee otro agente?

    Recuerdo

    El contexto guardado en su propia herramienta, que puede diferir.

    Sistema de registro

    El mismo registro, si usa la misma instancia y la misma entrada MCP o perfil de datos.

02 · Seguir un registro

Cómo un hecho pasa a ser actual

Ejemplo

La factura INV-2041 llega en PDF con vencimiento el 22 de octubre. Un correo facilitado después cambia el vencimiento al 29 de octubre de 2026. Un agente conectado ve el valor seleccionado del 29 de octubre y puede inspeccionar qué observación lo proporcionó. El importe sigue viniendo del PDF.

  1. Paso 01 · Fuente

    Conserva el material original

    Facilita el PDF o el correo de la factura como fuente para poder inspeccionar su contenido.

    Lee la guía
  2. Paso 02 · Observación

    Extrae y registra hechos

    Un agente extrae los campos de la factura y registra una observación vinculada a la fuente facilitada.

    Lee la guía
  3. Paso 03 · Entidad

    Identifica la entidad de forma determinista

    El número, el proveedor y la fecha identifican esta factura; las observaciones posteriores pueden referirse a ella.

    Lee la guía
  4. Paso 04 · Valores actuales

    Calcula los valores actuales

    Neotoma aplica automáticamente la regla del campo. Aquí cambia el vencimiento y el PDF sigue aportando el importe.

    Lee la guía
  5. Paso 05 · Instantánea

    Lee el valor actual

    La instantánea muestra los valores seleccionados por las reglas y las observaciones que los respaldan.

    Lee la guía

Una factura, cinco partes

  1. 1Dos fuentes discrepan sobre una factura: el PDF indica vencimiento el 22 de octubre y un correo posterior el 29 de octubre.
  2. 2Cada fuente se convierte en una observación. Aquí, una regla de última escritura por campo calcula el valor actual.
  3. 3El vencimiento pasa al 29 de octubre. El campo modificado apunta a la observación posterior.
  4. 4El importe sigue viniendo de la primera observación. Ambas permanecen registradas.
  5. 5Los agentes escriben cada fuente como observación y leen la instantánea actual. Las escrituras por MCP también registran el nombre de cliente que declara el cliente.

Un agente vinculó explícitamente estos registros de ejemplo. El PDF y el correo facilitados siguen siendo fuentes de observaciones; el registro de correo tipado y la tarea de seguimiento son registros separados y no se crean automáticamente a partir de esas fuentes.

# Perfil local. Sustituye cada clave de ejemplo; reutilízala solo para reintentar la misma operación.

# Toma el entity_id devuelto como INVOICE_ID.

neotoma dev store \
  --observation-source import \
  --idempotency-key unique-invoice-store-key \
  --entities '[
  {
    "entity_type": "invoice",
    "schema_version": "1.0",
    "invoice_number": "INV-2041",
    "vendor_name": "Acme",
    "invoice_date": "2026-10-01",
    "amount_due": 3200,
    "currency": "USD",
    "date_due": "2026-10-22"
  }
]'

# El correo facilitado cambia el vencimiento. Usa el ID de entidad devuelto arriba.

neotoma dev corrections create "$INVOICE_ID" \
  --entity-type invoice \
  --field-name date_due \
  --corrected-value 2026-10-29 \
  --idempotency-key unique-amendment-key

neotoma dev entities get "$INVOICE_ID"

neotoma dev observations list --entity-id "$INVOICE_ID"

neotoma dev request --operation getFieldProvenance \
  --body "{
  \"entity_id\": \"$INVOICE_ID\",
  \"field\": \"date_due\"
}"
# Configura NEOTOMA_URL y tu token de propietario. Sustituye INVOICE_ID después de store.

Cada store y cada corrección por MCP o REST necesita su propia clave de idempotencia. En una instalación local predeterminada, MCP stdio y CLI o REST escriben como usuarios locales distintos y mantienen registros separados salvo que compartan instancia y usuario. Los comandos de corrección conservan la observación anterior, pero no guardan un documento fuente.

03 · Conectar

Empieza en tu herramienta de IA preferida

Neotoma puede ejecutarse localmente o detrás de un punto de acceso autenticado. Los agentes conectados usan MCP, la API REST o la CLI para leer y escribir registros en una instancia configurada.

Configura cada herramienta con la misma instancia y el mismo perfil de datos para trabajar con los mismos registros; distintas entradas pueden utilizar bases de datos separadas. La aplicación incluida permite inspeccionarlos.

He elegido la vía de instalación compatible para una instancia que administro. Consulta la guía de Claude Code para comprobar los requisitos y límites de esta vía.

Permisos opcionales de comandos para Claude Code

Una denegación o un alcance desconocido exige revisar permisos, no ampliarlos automáticamente.

Permisos opcionales de comandos para Claude Code

Este fragmento opcional escribe en el archivo indicado. Las autorizaciones amplias, como Bash(neotoma:*) en Claude Code y neotoma * en Cursor o Codex, pueden permitir cualquier subcomando de Neotoma, incluido reset, sin otra solicitud del entorno. Revisa el alcance completo antes de copiar. Si se deniega un permiso o desconoces su alcance, inspecciona la configuración del entorno en vez de ampliarlo automáticamente.

Claude Code permisos

Fragmento de configuración para Claude Code. Archivo de destino: .claude/settings.local.json (proyecto) — o ~/.claude/settings.json (usuario)

// Pega esto en .claude/settings.local.json (proyecto) o ~/.claude/settings.json (usuario).
// Combínalo con la lista existente de "permissions.allow", si la hay.
{
  "permissions": {
    "allow": [
      "Bash(neotoma:*)",
      "Bash(npm install -g neotoma:*)"
    ]
  }
}
